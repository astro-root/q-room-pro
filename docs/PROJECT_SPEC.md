# Q-Room Pro 要件定義（MVP）

## プロダクト
競技クイズの出題・早押し・正誤判定・スコアをひとつのゲームルームで管理する。PCは司会とスコアボード、スマートフォンは大きく即応するプレイヤー操作を主眼にする。

## MVPの対象
- 司会がブラウザー上でルームを作り、別端末のプレイヤーがルームコードで参加できる。
- ルーム名、プレイヤー名、7○3×、10by10、または正解数/失格誤答数を指定したn○m×を選ぶ。
- ゲーム開始、早押し、正誤判定、次問、終了、順位・得点・○×表示。
- 出題ごとの20秒カウントダウンと、司会による回答なし処理。
- タッチ端末で即時の押下表示と利用可能端末での短い振動を行う。
- 入力名をHTMLとして解釈せず、ゲーム状態は有効な遷移だけを受け付ける。

## MVP対象外
アカウント、永続的な履歴、問題データベース、チャット、課金、ランキング、Bluetooth/Wi-Fi Direct、高度なカスタムルール、ネイティブ配布。

## 画面
1. ホーム：ルーム作成への導線。
2. ルーム作成：名前、ルール。
3. 参加：ルームコード、プレイヤー名。
4. ルーム：ルームコード、現在の状態、司会操作、プレイヤー一覧、得点・○×。
5. プレイヤー画面：一人分の得点・○×と大型の早押し操作。
6. 結果：終了時に順位と各プレイヤーの記録。

## 受け入れ条件
- ルールを選んで複数プレイヤーのゲームを開始できる。
- 出題中のみ有効プレイヤーが早押しでき、先着一人だけが回答者となる。
- 司会の正誤判定が○×、得点、失格、終了判定へ反映される。
- 誤答時は誤答者を同じ問題の受付から外し、ほかに回答可能なプレイヤーがいれば受付を続ける。
- 7○または10○で勝者を確定する。7○3×では3×で失格とする。
- n○m×では設定された正解数で勝利し、設定された誤答数で失格とする。
- リセット後に初期状態へ戻る。

## 制約と品質
ルーム状態はサーバーメモリに保持し、プロセス再起動で失われる。ブラウザーの振動API、音声自動再生、全画面表示は端末・権限に左右される。サーバー受信順で裁定し、物理押下時刻の同時押し公平性は保証しない。
