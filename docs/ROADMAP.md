# 開発ロードマップ

## Phase 1: コア体験（実装済みのWeb試作）
- ルーム作成、ルームコード参加、7○3×・10by10、状態遷移、20秒問題タイマー。
- 早押し、司会判定、スコア、結果表示。
- HTTP操作 + SSE同期、サーバー権威の状態遷移、簡易認証・レート制限。
- 「回答なし」処理、狭い画面レイアウト、ローカル振動API、大型プレイヤー画面。

## Phase 2: ドメイン品質
- 状態遷移・ルール境界値・得点計算を自動検証。
- 同点順位、誤答後の受付再開など競技運用仕様を確定。
- アクセシビリティと実機タッチ遅延を確認。

## Phase 3: オンラインルームの強化
- イベントIDによる冪等性、再接続時の状態復元とホスト引き継ぎ。
- 永続ストアとイベント履歴を追加し、プロセス再起動後の復旧を可能にする。
- 切断中の表示、遅延計測、複数接続での負荷を扱う。
- 必要性を計測してからSSE/HTTPをWebSocketへ移行するか決める。

## Phase 4: 製品UIと端末対応
- Web運営画面・スコアボードを整備し、PWA化（マニフェストとオフライン用アプリシェルは実装済み。ルーム機能はオンライン必須）。
- iOS/Android実機でタッチ、触覚、音声、画面ロック等を評価。
- Capacitor設定、Android/iOSプロジェクト、ネイティブ資産同期、App/Haptics/Share連携を実装済み。API接続先・CORS・触覚・安全な保存・戻る操作を実機検証。

## Phase 5: 運用拡張
- オフライン単一端末ゲームの保存・復元を設計。
- 同期競合やイベント履歴の保持方針を定めてから永続化。
- 問題管理、追加ルール、大会機能は利用実績に基づき選定。

## 最初に続けて実装する機能
ドメイン遷移の自動検証、同点順位とルール別ペナルティ時間の運用仕様を確定する。次に永続化・再接続とPWA対応へ進む。
