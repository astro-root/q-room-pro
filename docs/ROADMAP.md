# 開発ロードマップ

## Phase 1: コア体験（実装済みのブラウザー試作）
- ルーム作成、プレイヤー登録、7○3×・10by10、状態遷移。
- 早押し、司会判定、スコア、結果表示。
- 操作の視認性、狭い画面レイアウト、ローカル振動API。

## Phase 2: ドメイン品質
- 状態遷移・ルール境界値・得点計算を自動検証。
- 同点順位、誤答後の受付再開など競技運用仕様を確定。
- アクセシビリティと実機タッチ遅延を確認。

## Phase 3: オンラインルーム
- API、認証不要の参加フロー設計、ホスト/プレイヤー権限。
- WSSによるルーム同期、サーバー権威のイベント・得点処理。
- 切断、再接続、重複イベント、通信遅延を扱う。

## Phase 4: 製品UIと端末対応
- Web運営画面・スコアボードを整備し、PWA化。
- iOS/Android実機でタッチ、触覚、音声、画面ロック等を評価。
- 必要性が検証できた場合にCapacitorラッパーとネイティブAPIを導入。

## Phase 5: 運用拡張
- オフライン単一端末ゲームの保存・復元を設計。
- 同期競合やイベント履歴の保持方針を定めてから永続化。
- 問題管理、追加ルール、大会機能は利用実績に基づき選定。

## 最初に続けて実装する機能
ドメイン遷移の自動検証と、司会用の問題タイマー・「回答なし」操作。続いてサーバー同期に進む前に、誤答後の再受付方法とルール別ペナルティ時間を確定する。
